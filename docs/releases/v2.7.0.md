# v2.7.0

## 日程先落在本机，再和飞书对账

从 v2.3.0 到这一版，改的不是界面，是这个应用的**数据来源**。

以前每次启动、每次翻月，都要起一个 `node` 子进程去问飞书；断网就是白板，翻页就是干等，周视图跨月还会漏掉日程——因为拉取区间写死成「本月」。现在本机有一份 SQLite 事实层，视图先读它出图，再拿远端结果校准。四个版本（v2.4.0 → v2.7.0）在这层地基上依次长出提醒、统计和命令行。

### 本地事实层（v2.4.0）

- `events.db` 与 `config.json` 同目录（Windows 便携版在 EXE 旁边，macOS 在 `~/Library/Application Support/FeishuCalendar/`），三张表：日程、已同步区间、已提醒记录。WAL 模式，只依赖标准库。
- **视图感知拉取**：月视图取本月 ±7 天（月历网格最多前后各溢 6 天），周视图取周一至周日 ±7 天。区间由 `utils.view_range()` 单一出口计算，跨月不再漏项。
- **增量写入**：同步结果按 `event_id` upsert，只清理本次同步窗口内已消失的日程。上游删掉的会跟着消失，窗口外的历史不会被误伤。
- **空响应不等于删除**：只有拿到真正的列表才动库；`None` 或异常结构一律跳过。飞书说没有，和飞书没回答，是两件事。
- 断网时只弹一条 Toast 并标注「离线 · 本地缓存 N 项」，不抢视图；搜索先查本地索引，服务端结果按 `event_id` 合并去重。
- 370 天滚动保留；库文件损坏会被隔离重建（下次同步自动填回），绝不因为缓存问题启动失败。

### 主动提醒（v2.5.0）

在此之前，这个日历从不说话。

- 会前 0/5/10/15/30/60 分钟弹系统通知。去重键是**某一次发生**（`<event_id>@<start>`）而不是事件本身——每周例会下周还要再提醒，同一场刷新一分钟后不能重复提醒。
- 记账写在发通知之前：宁可漏一条，也不重复轰炸。
- 已经开始的日程不再补提醒（30 秒宽限），笔记本合盖唤醒后不会事后大喊。
- 冲突与超载按整天取数，早上就能看到下午的重叠；超载阈值默认 6 小时，同类告警每天最多一次。
- 免打扰支持跨零点（如 22:00–08:00），命中时直接返回且**不记账**，静音期不会白白消耗提醒名额。
- 托盘标题动态化：「今天 3 项 · 14:30 评审」，不打开窗口也知道下一条是什么。
- 可选的「今日条」：无边框置顶窄条，可拖动、可关闭，点一下打开主窗口。

### 统计与导出（v2.6.0）

有了本地事实层，这两件事才有意义。

- 月热力图（今天描边、悬停看明细）、负荷摘要、星期分布，支持按月翻页，深浅两套配色。
- 分档阈值 60 / 120 / 240 分钟，0 分钟必须落在空白档；全天日程计入事项数但**不计入时长**，否则一个公司假日就能把会议小时拉满。
- 定时导出（回看 7 天 / 前瞻 30 天）为 `events-YYYYMMDD.json` 与 `.csv`，原子写；`export_last_run` 在文件落盘成功后才推进，失败下次重试而不是跳过一整天。

### 命令行与后端协议（v2.7.0）

- `python -m headless today|next|range|search`，支持 `--json`、`--source store|lark|ics`、`--db`、`--ics`、`--limit`，退出码 0/1/2。默认读本地库，**不需要登录态、不需要显示环境、不 import PySide6**。
- `CalendarBackend` 协议与三个实现：`LarkCliBackend`（走 lark-cli 读写）、`StoreBackend`（本地只读）、`IcsBackend`（读导出的 `.ics`，处理折行与 `VALUE=DATE`）。只读后端执行写操作直接抛 `ReadOnlyBackend`，不允许静默成功。
- 主窗口**故意不接**这个协议：它是同步的，把刷新塞进同步调用会让界面卡几秒。窗口继续走 QProcess 异步路径，协议服务于命令行与测试——这条边界写在 `AGENTS.md` 里，免得后来者当成死代码去「优化」。

```bash
python -m headless next --json            # 下一条日程，给脚本 / Stream Deck
python -m headless range --start 2026-11-01 --end 2026-11-30
python -m headless search 评审 --source store
```

### 隐私说明变更（重要）

旧版 README 写着「日程不在本地持久化」——**这句话现在不成立了**。

日程标题、起止时间、组织者、描述与会议链接会写入本机 `events.db`，用于离线查看与提醒去重。数据不出本机、不上传任何第三方；删除应用目录（或单独删掉 `events.db`）即可彻底清除，下次同步会重建。README 的隐私章节已同步改写。

### 升级

- v2.3.0 的用户会收到增量补丁（以 v2.3.0 的 EXE 为基座）；更早版本自动回退全量下载，行为与以前一致。
- 这次补丁收益不如上次：**全量 55.13 MiB → 补丁 41.30 MiB，省 25%**（v2.3.0 那次是省 94%）。原因是 PySide6 从 6.5 升到 6.12，Qt 的二进制几乎都换了——245 个归档成员里有 62 个发生变化，可复用的只剩 Python 侧那部分。补丁本身已实测可用：用 v2.3.0 的 EXE 应用补丁重组，结果 SHA-256 与官方全量逐字节一致。
- 首次启动 v2.7.0 时本地库是空的，视图会先空白一次再随同步填充。之后翻月不再联网。
- 统计、今日条、定时导出、提醒在 README 中标注为实验性功能，设置项集中在「提醒」Tab 与通用页的「定时导出」组，可随时关掉。

### 已知限制

- 今日条首次落位按主屏右下角计算；在多显示器上拖到坐标含负值的副屏后，下次启动可能回落到默认位置。
- 冲突与超载告警按整天取数，跨零点的深夜日程只在其开始当天计入。
- 覆盖率门禁（`--cov-fail-under=70`）已本地验证（应用代码 74.88%），但尚未进入 CI——推送该改动需要带 `workflow` 权限的凭据，留待后续。

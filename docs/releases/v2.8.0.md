# v2.8.0

## 装不上，就自己装

v2.7.0 之前，这个应用有个很挫的门槛：没装 `lark-cli` 就只剩一块写着安装命令的面板，让你自己复制到终端。按钮还叫「我已安装，重试」——它不装，它等你装。

这一版把这条链补齐了，顺带修掉一个在实机部署时才暴露的桌面快捷方式缺陷。

### 应用内自动安装 lark-cli

首次启动检测不到飞书官方命令行工具时，面板主按钮变成**「自动安装 lark-cli」**。点之前弹确认框，把即将执行的确切命令写明白，点完逐行输出 npm 的真实日志，300 秒超时，中途可取消。

- **判定成功的条件不是「npm 退出码是 0」**，而是「退出 0 **且** `which lark-cli` 真的找得到」。这两件事经常不是一回事，只认前者就会出现「npm 说装好了、应用还说找不到」。
- **装完立刻刷新 PATH。** macOS 上从 Finder 启动的 `.app` 只继承一份极简 PATH，npm 的全局 bin 目录根本不在里面——不刷，等于白装。
- **启动时兜底探测**：`which` 不到 CLI 时，向 npm 问一次全局 prefix 并补进 PATH。终端里手工装过的老用户，重启应用就能被识别，不必再折腾。
- **没装 Node.js** 时按钮换成「去下载 Node.js」，直接打开官网。
- **不自动提权。** 全局目录不可写时只给建议（改用用户级 prefix，或自己决定要不要 sudo）。在用户机器上装东西已经够越界了，跨过提权那道线必须由人点头。
- npm 的常见报错被翻成能照做的中文：`EACCES` → 权限问题与该改哪、`ETIMEDOUT` → 网络或镜像源、`E404` → 包名/源配置不对。

实现上按项目既有分法拆成两层：`cli_installer.py` 是纯逻辑（探测、构造命令、刷 PATH、翻译报错），`cli_install_async.py` 是 QProcess 外壳。

### 桌面快捷方式：冻结包其实一直建不出来

首次运行会在桌面放一个快捷方式，代码注释写着「失败不阻塞启动，下次运行会重试」。实际行为是反的：

1. `_create_macos_shortcut` 只认源码目录下的 `dist/飞书日程.app`，打包后的 `.app` 里这个路径不存在，函数静默跑完，什么也没建；
2. `_ensure_desktop_shortcut` **无论成败**都把 `desktop_shortcut_created` 写成 `true`，于是「下次重试」永远等不到。

也就是说，发出去的安装包从来没有真正建过快捷方式，而 `config.json` 一直声称建好了。

现在三个创建函数返回 bool，只有真建出东西才写标记；冻结版从 `sys.executable` 往上找 `.app` 链自身。Windows 冻结版同样受累（`__file__` 指向打包进 pyz 的路径），一并改为以 EXE 为目标。

> 已经装着 v2.7.x 的用户**不会**被自动补建快捷方式——标记还是 `true`，这是尊重「用户可能主动删掉了桌面图标」。想现在就要：把 `config.json` 里 `desktop_shortcut_created` 改成 `false` 再启动一次即可。

### 开发侧：门禁搬到本地

线上 CI 的覆盖率门禁（`--cov-fail-under=70`）因为推送凭据缺 `workflow` 权限，一直推不进仓库。既然线上跑不了，就让它在你按下 push 之前跑：

```bash
python3 tools/ci.py                  # ruff → compileall → pytest + 覆盖率 ≥70%
python3 tools/ci.py --fast           # 跳过覆盖率统计
python3 tools/ci.py --build          # 额外打一次本机安装包
python3 tools/ci.py --install-hook   # 装 pre-push 钩子
```

与线上 `ci.yml` 同源：同样的三条命令、同样的 compileall 排除规则，补上线上缺的阈值。一次约 20 秒。顺手把 PySide6 导入期写入工作目录又删掉的 `shibokensupport/*`、`signature_bootstrap.py` 从覆盖率分母里排除——它们会让覆盖率莫名漂移并刷一屏警告。

当前应用代码覆盖率 **76%**，468 例通过。

### 升级

- 增量补丁以 **v2.7.0** 的 EXE 为基座（自动取上一个带 EXE 的发布）。这一版只动 Python 源码、PySide6 未变，补丁体积应远小于上次。
- 更早的版本自动回退全量下载，行为与以前一致。
- 从 v2.7.x 升级不影响本地 `events.db`，日程、已提醒记录、导出进度都原样保留。

### 已知限制

- 自动安装走的是 npm 的**全局**目录。若 Node.js 是某个工具链自带的（例如随其他软件升级换了版本），lark-cli 会随之失联，重装一次即可。
- 只处理 npm 全局安装路径，`pnpm` / `yarn` 的全局 bin 不做探测。
- 不自动配置 `npm config set prefix`，也不处理需要管理员权限的系统级 Node。
- 自动安装完成后仍需扫码授权，这一步无法自动化。

# v2.9.0

## 扫码登录，从来没成功过

这是这一版最要紧的一件事，而且是个很蠢的 bug。

登录窗口的二维码一直是「二维码不可用」。不是偶尔，是**每次**。原因是一行参数：

```python
self._lark_cli(["auth", "qrcode", url, "--output", "qr.png", "--size", "256"])
```

`lark-cli auth qrcode` 的官方用法是 `lark-cli auth qrcode <url> --output ./qr.png`，**没有 `--size`**。参数不认识，命令就以非零码退出，图片自然没生成，界面停在失败态；而登录流程必须要扫码才能往下走——也就是说，任何一台新机器想登录，都只能绕到网页授权那条路，二维码形同虚设。

修法不是把 `--size` 删掉，而是**不再依赖外部命令画二维码**：新增 `qrgen.py`，直接在本地把 URL 编成模块矩阵，再按整数倍缩放画进位图。

为什么不装个现成库（`qrcode` / `segno`）？为一张固定尺寸、内容就是一条短 URL 的图引入一个新依赖，得同时改 `build_macos.sh` 和 `build_windows.ps1` 的 `--hidden-import` 清单，两个打包脚本都得重新验证一遍；而这套编码逻辑本身不到 400 行，且**永不需要联网、不需要 node 子进程、不受 cli 版本差异影响**。顺带它还解决了另一个隐患：以前生成过程要在临时目录落一张 PNG，现在连文件都不写了。

实现按规范来，没有走捷径：

- Byte 模式 + 纠错等级 **M**，版本 1–10 自动选（登录 URL 落在版本 5，37×37 模块）
- Reed-Solomon 在 GF(256) 上算，生成多项式、分块交织、版本信息、格式信息（BCH）齐全
- 8 种掩码全试一遍，按标准那 4 条罚分规则挑最低分的
- 数据放置走锯齿路径，跳过第 6 列（那条竖向 timing 图案）

验证方式分两层，都在 `tests/test_qrgen.py`：一条固定向量（同一 URL 必须编出同一张图，防止以后动代码把它改坏），一条端到端——用 OpenCV 把生成的图**解出来**，比对明文是否等于原始 URL。开发过程中这两层各抓到一次真 bug：格式信息的坐标映射写反了（副本一的上半段和下半段接错），以及数据放置前没先占住格式信息区（导致数据整体前移 15 位）。肉眼完全看不出差别，解码一跑就现原形。

> 顺带说明：OpenCV 只用于**测试**（`pytest.importorskip`，没装就跳过），没有进 `requirements.txt`。应用本身除了 PySide6 和 openpyxl 依然不需要任何第三方包。

## 首页那个「正在连接飞书」换掉了

原来是 `QProgressBar` 设 `range(0, 0)`——系统那种来回扫的灰条。它和这套「深色台面 + 青蓝光晕 + 极细线」的设计语言没有任何关系，而且只有一维的往返，看两秒就像卡住了。

现在是一颗自绘光弧（`widgets.ConnectingOrb`），三层同时在动，周期互质，肉眼抓不到重复的节拍：

| 层 | 周期 | 动作 |
| --- | --- | --- |
| 角度 | 1500ms | 匀速顺时针转圈 |
| 角宽 | 2600ms | 78° → 158° → 78°，像在吸气吐气 |
| 呼吸 | 2100ms | 外圈光晕的透明度随之起伏 |

细节上做了几件不太显眼、但决定「是不是高级」的事：

- **弧用锥形渐变**，弧头最亮、弧尾淡出到全透明，再在弧头补一小团径向光斑。少了这团光，圆头笔帽在深色底上看起来像被剪断的线段。
- **光晕的亮度峰值压在轨道半径上，不是圆心**。圆心亮起来会变成一块蓝色圆饼。
- **转圈必须匀速**。任何缓动曲线都会让每一圈在同一个角度慢下来，变成肉眼可见的「顿一下」；呼吸类才用 `InOutSine`。
- **顺时针**。逆时针「有道理」，但用久了总觉得反着来。
- **隐藏即停**：面板切走后动画立即 stop。这是个常驻桌面的小挂件，没人看的时候还跑 60fps 重绘是白烧电。
- 深浅两套配色分别调过：浅色底上光晕要压到几乎看不见，弧身渐变要更实，否则整段弧像褪了色。

## 设置窗：内容重新组织，把「量尺寸」这件事故意做对

五个分页统一了骨架——字段名定宽 76px、单行输入框定宽 150px、右侧数值右对齐 44px，组框标题压在边框线上：

- 「通用」页五组并为四组：开机启动与版本更新合成「启动与更新」；「自动刷新」改名「刷新」
- 「提醒」页把三条勾选框拆成「勾选框 + 独立字段行」，阈值不再挤在一句话里
- 「账号」页补「数据来源」组（当前由 lark-cli 提供）
- 「关于」页补「运行环境」组：数据目录、Python / Qt / 系统版本
- 超长路径一律尾部省略，完整值放 tooltip

窗口尺寸改成**由内容决定**（当前 560×671），内容再多就走 `QScrollArea`。上一版用 `setFixedSize` 关窗，`QVBoxLayout` 在空间不够时会把 QLabel 压到 0 高、把控件叠在一起，而且不报错——设置窗和统计窗都栽过同一个坑。

几处不写出来就会被后人再踩一遍的细节：

- **QSS 一旦定制 `::drop-down` / `::up-button`，Qt 就不再画默认箭头**，得自己给 `image: url(...)`。这版补了四个 chevron SVG。
- **`QAbstractSpinBox` 的内部编辑区是自绘的**，外层 `:disabled { color }` 到不了文字，会出现「禁用后反而更亮」。改成整块挂 `QGraphicsOpacityEffect(0.42)`。
- **`QSS min-width` 会覆盖 `setFixedWidth`**（`QStyleSheetStyle` 用 `setMinimumWidth` 实现），下拉框宽度对不齐就是这个原因。
- 基础层那条 `QWidget { background-color }` 会把行容器也刷上窗口底色，浅色主题下每个组框里多出一道浅灰横条。行容器统一 `objectName="formRow"` 后单独透明化。

## 升级

- 增量补丁以 **v2.8.0** 的 EXE 为基座：**全量 55.19 MiB → 补丁 3.16 MiB，省 94.3%**。本版只动 Python 源码与四个 SVG，PySide6 未变，可复用的面很大。更早的版本自动回退全量下载。
- 升级不影响本地 `events.db`，日程、已提醒记录、导出进度都原样保留。
- 二维码改由应用自己绘制，**不再需要 lark-cli 支持 `auth qrcode` 的 `--size`**，任何 cli 版本下都能出图；扫不出来时下方链接与「复制链接」始终可用。

## 已知限制

- 二维码编码器只实现 Byte 模式与纠错等级 M。登录 URL 远在容量之内，但如果哪天要编更长的内容（纠错等级 M 下上限 213 字节）会直接抛错，而不是降级换版本——报错比悄悄编错强。
- 加载动效是自绘，`QSS` 改不动它；换配色要去 `theme.PAINT` 的 `beam_from` / `beam_to`。
